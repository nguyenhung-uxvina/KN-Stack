Identify high-leverage intervention points in a system to resolve persistent design problems.

Usage: /leverage [problem_description] OR describe the system interactively.

1. If $ARGUMENTS provided, use as initial problem description; otherwise ask:
   - What persistent problem or design challenge are you trying to solve?
   - What system is this part of? (product, organization, process)
   - What have you already tried that hasn't worked?
2. Execute the leverage point analysis using Donella Meadows' 12 leverage points:
   MAP the system:
   - Identify key stocks, flows, feedback loops
   - Draw causal structure (text form if no diagram tool)
   RANK leverage points from lowest to highest impact:
   12. Numbers (parameters) -- weakest
   11. Buffer sizes
   10. Stock-and-flow structure
   9.  Time delays
   8.  Strength of negative feedback loops
   7.  Gain of driving positive loops
   6.  Structure of information flows
   5.  Rules of the system
   4.  Power to add/change/evolve system structure
   3.  Goals of the system
   2.  Mindset or paradigm
   1.  Power to transcend paradigms -- most powerful
   IDENTIFY: Top 3 leverage points for THIS specific problem
   RECOMMEND: Specific interventions at each leverage point
   WARN: Leverage points can cause unintended consequences -- flag risks for each intervention
3. Output: Leverage map + top 3 interventions with risk flags

SYSTEMS RULE: Start with structure, not symptoms. Pushing harder on a failing structure makes it fail faster.
USE WHEN: Stuck on a recurring problem, or before committing to a major design decision.
