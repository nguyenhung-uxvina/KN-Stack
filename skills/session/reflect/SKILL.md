Run a D-M-I-R weekly reflection to extract and compound learning.

Usage: /reflect [week_ending_date] OR run interactively for current week.

1. If $ARGUMENTS provided, use as week_ending_date (YYYY-MM-DD); otherwise use today's date
2. Ask for (or infer from context):
   - Which projects were active this week? (VN-XXX-XXX codes)
   - Which of the 9 skills was the primary focus? (S1-S5, B-EI/CP/AL/NS)
   - Actual time allocation this week (hours per skill category)
3. Execute the D-M-I-R reflection:
   DIAGNOSE -- What actually happened this week? Facts only. What surprised you? What broke?
   MODEL -- Why did it happen? What system/pattern caused it? (use causal thinking, not blame)
   INTERVENE -- What would you do differently? What's one specific change for next week?
   REFLECT -- What did you learn about yourself as a designer/engineer/thinker?
   CONSTRAINTS: honest (real mistakes, not just successes), specific (no generic insights), actionable (1 change minimum)
   LENGTH: 300-500 words across 4 sections
4. Present reflection to user for review. Save to:
   `2_Areas/HELIX — Design Execution/Design-Review-Log/{{YYYY-WW}}_weekly_reflect.md`

HONESTY RULE: Surface real mistakes. Generic "I learned to be more careful" entries are invalid -- ask for specifics.
FREQUENCY: Every Friday. Non-negotiable. No reflection = no compounding.
